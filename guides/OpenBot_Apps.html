Apps im OpenBot-Marketplace

Apps geben deinen Agents Zugriff auf externe Dienste, von Design-Tools über Datenbanken bis zu Automatisierungsplattformen. So funktionieren sie und so findest du die richtigen für deinen Workflow.

254 Apps 8 Kategorien 1000+ Dienste via Composio Marketplace

GrundlageWas sind Apps in OpenBot?

Im Marketplace stehen unter dem Tab Apps Plugins, die ein Agent aktiv nutzen kann. Jede App erweitert den Agent um neue Fähigkeiten: Er greift auf externe Dienste zu, ruft Daten ab, löst Aktionen aus oder erstellt Inhalte, ohne Umweg über den Browser.

Der Unterschied zu Skills: Skills beschreiben, wie ein Agent denkt und handelt (Schreibstil, Struktur, Rollenverhalten). Apps beschreiben, womit er handelt: konkrete Verbindungen zu Figma, Notion, Supabase, Stripe und Hunderten weiterer Dienste.

Wichtig: Apps laufen auf deinem eigenen Computer. OpenBot kennt keine Chat-Verläufe oder Befehle, es stellt nur die Verbindung zwischen Agent und Dienst her. Zugangsdaten bleiben bei dir.

Was eine App technisch tut

Jede App stellt dem Agent eine Reihe von Tools bereit: strukturierte Funktionen, die er im Rahmen einer Aufgabe aufrufen kann. Eine Notion-App hat etwa „Seite erstellen“, „Datenbank abfragen“ oder „Block aktualisieren“. Der Agent entscheidet selbst, welches Tool er wann einsetzt.

Apps erscheinen im Marketplace mit einer Versionsnummer (z. B. v1.1.1), damit du weißt, welchen Stand du installiert hast und ob Updates vorliegen.

Teil 3 · Brücken-Apps

Teil 3Zapier und Composio: die Brücken-Apps

Zwei Apps verbinden Agents nicht mit einem einzelnen Dienst, sondern mit Hunderten gleichzeitig.

1.000+ Dienste

Composio

Integrations-Plattform mit standardisierten Tools für über 1.000 Apps. Einmal installiert, erreicht dein Agent auch Dienste ohne eigenen Marketplace-Eintrag, von Slack bis Salesforce.

Automatisierungen

Zapier

Der Agent löst Zaps aus, die du in Zapier konfiguriert hast. Er muss die Ziel-App nicht kennen, er gibt nur einen Trigger weiter.

Wann welche Brücke?

  • Composio für direkte Tool-Calls: Der Agent führt eine Aktion in einem Dienst aus, Composio liefert das passende Tool zur Laufzeit.
  • Zapier, wenn du bestehende Automatisierungen weiterverwenden willst: Die Logik liegt in Zapier, der Agent löst nur aus.
  • Beide zusammen: Zapier für komplexe Multi-Step-Flows, Composio für direkte Einzelaktionen.
Composio und Zapier ersetzen keine nativen Apps, sie ergänzen sie. Gibt es Figma oder Supabase im Marketplace, nimm die native App: spezialisierter und mit weniger Overhead.
Teil 4 · Erste Schritte

Teil 4Apps installieren und nutzen

1

Marketplace öffnen

Zum Marketplace wechseln und den Tab Apps wählen. Nach Kategorie filtern oder direkt nach einem Dienst suchen.

2

App auswählen und verbinden

App anklicken und installieren. Dienste mit Authentifizierung (Notion, Stripe usw.) fragen nach API-Schlüssel oder OAuth-Login.

3

Agents festlegen

Auf der App-Seite im Bereich Agents auswählen, welche Agents die App nutzen. Standardmäßig bekommt jeder Agent jede App, auch neue; beschränke sie deshalb auf die Agents, die sie brauchen.

4

Im Gespräch nutzen

Der Agent entscheidet selbst, welche App-Tools er einsetzt. Du kannst ihn auch direkt ansprechen: „Erstelle eine Notion-Seite mit dem Ergebnis.“

5

Updates im Blick behalten

Ist eine neue Version verfügbar, zeigt der Marketplace einen Hinweis; bestehende Konfigurationen bleiben erhalten.

Sicherheit: Rechte pro Tool gibt es nicht; ein Agent bekommt eine App ganz oder gar nicht. Eingebaute Connectors (GitHub, Slack …) gelten immer für alle Agents. Hintergründe im Komplett-Setup-Guide.

Empfehlung für den Einstieg

Starte mit einer App für einen Dienst, den du täglich nutzt. Notion, Linear oder Supabase eignen sich gut, weil sie breite Tool-Sets haben und gut dokumentiert sind. Composio installierst du erst, wenn du einen Dienst ohne eigenen Marketplace-Eintrag brauchst.

Tipp: Teste neue Apps zuerst mit einem eigenen Test-Agent, bevor du sie produktiven Agents gibst. Original: Marketplace auf openbot.run ↗
