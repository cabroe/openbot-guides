01Was ist OpenBot?

OpenBot ist ein local-first Desktop-Workspace für persistente KI-Mitarbeiter. Er führt unterschiedliche Agent-CLIs und Modell-APIs über ein einheitliches Interface zusammen und stellt für jeden Agent einen eigenen Workspace, einen Nachrichtenspeicher und einen eingebetteten Browser bereit.

Unterstützte Providers

OpenBot läuft aktuell mit folgenden Providern und CLIs:

  • Coding CLIs: Codex, Claude Code (Antigravity CLI), Grok CLI, OpenCode, Gemini
  • IDE-Agents: Cursor, Cline, GitHub Copilot
  • Weitere: Kimi, Devin, Mistral Vibe, Hermes Agent
  • Custom: OpenAI-kompatible Endpunkte und eigene ACP-Agents

Jeder Provider nutzt seine eigene lokale CLI-Installation. OpenBot kopiert keine Credentials — jeder Provider verwaltet seinen eigenen Login-State.

Wichtig: Agents laufen mit danger-full-access und approvalPolicy: never. Sie können Dateien ändern, Befehle ausführen, das Netzwerk nutzen und den Browser steuern — ohne Bestätigung pro Aktion. Dies ist eine bewusste Produktentscheidung, keine Sicherheitslücke.

Lizenz

OpenBot steht unter der PolyForm Noncommercial 1.0.0-Lizenz. Für kommerzielle Nutzung ist eine separate Lizenz erforderlich — Details unter openbot.run/pricing. Bis 1. Dezember 2026 ist die kommerzielle Nutzung kostenlos.

02Installation

Anforderungen: macOS 13+ (Apple Silicon oder Intel)

  1. DMG-Datei von openbot.run herunterladen
  2. App in den Applications-Ordner ziehen
  3. Beim ersten Start Provider-CLIs über Settings → Providers einrichten

Builds sind signiert und notarisiert. Provider-CLIs lädt OpenBot auf Wunsch selbst herunter und pinnt die Version.

Anforderungen: Windows 10+ (x64)

  1. x64-Installer herunterladen und ausführen
  2. Neuere Releases sind signiert; ältere Releases sind es nicht
  3. Provider über Settings → Providers einrichten
Dynamic Island und Agent-Dock sind ab 0.67.0 auf Windows verfügbar.

Anforderungen: Linux x64 oder arm64

chmod +x openbot-*.AppImage ./openbot-*.AppImage

Ubuntu 23.10+ und Debian 13 benötigen ein AppArmor-Profil:

# AppArmor-Profil installieren sudo cp build/linux/openbot.apparmor /etc/apparmor.d/openbot sudo apparmor_parser -r /etc/apparmor.d/openbot

Wichtig: Niemals --no-sandbox verwenden.

Für einen dauerhaften Linux-Server gibt es ein Installationsskript, das einen systemd-Service auf Ubuntu 24.04 oder 26.04 einrichtet:

curl -fsSL https://openbot.run/install.sh | bash openbot login

Docker-Image läuft headless auf linux/amd64 und linux/arm64.

# Mit seccomp-Profil starten docker run --security-opt seccomp=openbot.json \ ghcr.io/nightly-labs/openbot:latest # Dann einloggen openbot login
Remote Desktop auf Docker-Servern zeigt ab 0.72.0 einen Desktop mit dem OpenBot-Logo.

OpenBot ist als Nix-Flake verfügbar:

nix run github:nightly-labs/openbot

Provider-CLIs einrichten

OpenBot kann die meisten Provider-CLIs selbst herunterladen und pinnen. Alternativ können bereits installierte CLIs über Umgebungsvariablen angegeben werden (siehe Konfiguration). Jeder Provider braucht einen eigenen Sign-in — OpenBot überträgt keine Credentials zwischen Providers.

04Architektur

Electron Main
Hauptprozess
Lokaler Codex App Server über stdio, Claude Agent SDK über Stream-JSON, SQLite-Event-Log, typisiertes IPC, sandboxed Browser-View.
Renderer
UI-Schicht
SolidJS. Preload exponiert nur eine typisierte window.openbot-API — kein direkter Zugriff auf Node aus dem Renderer.
Account API
Cloud-Backend
TanStack Start auf Cloudflare Workers, mit D1 (SQLite) und R2 (Objekte). Verwaltet Konten, Einladungen, Mitgliedschaften — nicht Chats oder Befehle.
Remote Access
WebRTC-Verbindung
Team-API auf Loopback; Clients verbinden via WebRTC. Signal überträgt nur Setup-Nachrichten, coturn ist der TURN-Relay-Fallback. Chats, Dateien, Remote-Desktop-Media bleiben lokal.

Package-Struktur

  • src/main — Electron-Hauptprozess
  • src/backend — Backend-Logik
  • src/preload — Preload-Script
  • src/renderer — SolidJS-UI
  • apps/auth-api — Cloudflare-Workers-API
  • apps/status — Statusseite
  • packages/contracts — Shared Types
  • packages/i18n — 15 Sprachen inkl. RTL (Arabisch, Hebräisch)

Dateianhänge

  • Bis zu 100 MB pro Datei
  • Bis zu 250 MB pro Nachricht
  • Bis zu 10 Dateien pro Nachricht
  • Unterstützte Typen: MP3, MOV, MP4, ZIP, SVG und alle weiteren Dateitypen

Provider-State

Jeder Provider CLI verwaltet seinen eigenen State in einem eigenen Home-Verzeichnis: ~/.codex, ~/.claude, ~/.grok, ~/.gemini, ~/.cursor, ~/.cline, ~/.kimi, ~/.copilot, ~/.vibe, ~/.hermes. OpenBot kopiert keine Credentials zwischen Providers.

Sicherheitshinweis: Lokaler Vollzugriff ist eine Produktentscheidung — kein Sicherheitsmodell. Agents können auf Host-Pfade außerhalb ihrer Workspaces zugreifen. Sicherheitslücken bitte über SECURITY.md melden, nicht in öffentlichen Issues.

Datenschutz

OpenBot exportiert anonymisierte Diagnosedaten — nur mit expliziter Zustimmung. Chats, Dateien und Befehle verlassen den lokalen Server nicht über Cloudflare. Die vollständige Datenschutzrichtlinie ist in PRIVACY.md im Repository dokumentiert.

Agent-Import

Agents können aus einem Grok-Bot-Export (.zip) importiert werden. Der Import unterstützt: Skills, Routinen, Memories, Workspace-Dateien — aber keinen Chat-Verlauf.

06Entwicklungs-Setup

Anforderungen

  • Bun 1.4.2
  • Node.js 24 (siehe .nvmrc)
  • Mindestens eine unterstützte Agent-CLI

Starten

bun install --frozen-lockfile bun run dev

Wichtige Dev-Befehle

BefehlBeschreibung
bun run devApp im Entwicklungsmodus starten
bun run dev:allApp + API gemeinsam starten
bun run checkAlle Checks ausführen
bun run typecheckTypeScript-Typen prüfen
bun run test:changedTests für geänderte Dateien
bun run dev:resetLokalen State zurücksetzen
bun run dev:seedTestdaten einfügen
bun run packageApp paketieren

Mobile

bun run mobile:go # Mobile-App starten bun run mobile:ios # iOS-Simulator bun run dev:mobile # Dev-Modus mit Mobile
