GrundlageDrei Setup-Optionen

OpenBot bietet Teams drei Wege, eine gemeinsame Umgebung zu betreiben. Der Unterschied liegt im Hosting und im Support-Umfang.

Selbst betrieben

Lokal

Einzelne Personen oder kleine Teams betreiben OpenBot auf eigener Infrastruktur. Volle Kontrolle, keine Hosting-Kosten, aber eigene Wartung.

Empfohlen für Teams

Managed Server

Der Anbieter hostet und wartet den Server. Agents, Automatisierungen und Personen teilen sich eine Umgebung, rund um die Uhr verfügbar.

Für Unternehmen

Custom Deployment

Umgebungen, Agents, Berechtigungen und Integrationen werden individuell um bestehende Workflows konfiguriert.

Wichtig: Beim Managed Server laufen Agents, Automatisierungen und Personen in einer gemeinsamen Umgebung. Cloudflare verwaltet Konten und Einladungen; Chats, Dateien und Befehle bleiben ausschließlich auf dem Server. Pläne und Preise stehen in Guide 10 der offiziellen Guides.
Teil 1 · Features

Teil 1Team-Features im Überblick

Betrieb

24/7-Agents

Auf Managed-Infrastruktur laufen Agents durchgehend, auch nachts, am Wochenende und wenn das Team offline ist.

Automatisierung

Geplante Routinen

Routinen laufen zu festen Zeiten oder in Intervallen, ohne manuelle Auslösung.

Zusammenarbeit

Multiplayer

Personen und KI-Mitarbeiter teilen sich einen Server. Channels, Threads und Delegierung koordinieren die Arbeit.

Zugriff

Remote und mobil

Verbindung vom Desktop oder Mobilgerät. Owner und Admins verwalten Agent-Einstellungen direkt aus der Mobile-App.

Zugriffs- und Sicherheitsfeatures

FeatureWas es leistet
RollenOwner, Admin und Mitglied mit unterschiedlichen Berechtigungen
MCP-Zugriff pro AgentJeder Agent bekommt nur die MCP-Server und Apps, die er braucht
VaultVerschlüsselter Speicher für Logins, API-Keys, Zahlungskarten und Kontakte; Zugriff pro Agent konfigurierbar
Audit-LogProtokoll der Server-Aktionen für Owner und Admins
OpenID ConnectFirmen-Anmeldung über bestehende Identity-Provider
Thread-ParallelitätslimitsPro Server und pro Agent konfigurierbar
Channel-BrowserrechteWelche Mitglieder den eingebetteten Browser nutzen dürfen
Grenzen kennen: Der Audit-Log protokolliert Beitritte, Rollen und Agentenstufen, aber keine Agentenaktionen. API-Keys im Vault können Agents auf demselben Systembenutzer gegenseitig lesen. Details im Komplett-Setup-Guide.
Team-Einladungen: Personen werden über WebRTC zu einem bestehenden Server eingeladen. Die Team-API bleibt auf Loopback; Cloudflare überträgt nur Setup-Nachrichten, keine Chats oder Befehle.
Teil 2 · Implementation

Teil 2Implementation Services (Custom)

Für Unternehmen mit komplexen Anforderungen bietet OpenBot einen begleiteten Deployment-Prozess:

1

Infrastruktur-Setup und Konfiguration

Server-Umgebung auf eigener oder verwalteter Infrastruktur, abgestimmt auf IT-Landschaft und Sicherheitsanforderungen.

2

Initiale Agent-Konfiguration

Agents für bestimmte Rollen, Workflows und Zugriffsrechte, mit passenden Skills, Apps und Instruktionen.

3

Integration mit bestehenden Tools

Anbindung an interne Systeme, Datenquellen und Toolchains über Marketplace-Apps oder eigene Integrationen.

4

Custom Features und Workflows

Individuelle Workflows, Automatisierungen und Features über den Standardumfang hinaus.

5

Laufende Wartung und Weiterentwicklung

Support, Updates und Anpassungen nach dem Deployment, für Unternehmen ohne eigene OpenBot-Expertise.

Das Modell richtet sich an Unternehmen, die Agents abteilungsübergreifend einsetzen, an Agenturen, die Agent-Umgebungen für Kunden aufbauen, und an Organisationen mit besonderen Datenschutz- oder Compliance-Anforderungen.

Teil 4 · Erste Schritte

Teil 4Erste Schritte für Teams

Option A: Managed Server einrichten

1

Server erstellen

Settings → Server öffnen und Hosted Server erstellen wählen.

2

Standort und Speicher

Hosting-Standort und Speichertier auswählen.

3

Mitglieder einladen

Über Settings → Mitglieder → Einladen.

4

Rollen vergeben

Owner, Admin oder Mitglied.

5

Agent-Defaults

Unter Server-Einstellungen → Agents konfigurieren.

Option B: Einem Server beitreten

1

Einladung erhalten

Der Server-Owner schickt einen Einladungslink.

2

Beitreten

OpenBot → Server beitreten öffnen und den Einladungscode eingeben.

3

Verbinden

Die Verbindung läuft über WebRTC; ein direkter Netzwerkzugang zum Server ist nicht nötig.

Empfohlene Ersteinrichtung

  • Einen Firmen-Agent als Kontext-Halter für firmenweite Informationen einrichten (Modell aus Firmen & Projekte).
  • Den Audit-Log von Anfang an nutzen; rückwirkende Logs gibt es nicht.
  • MCP-Zugriffsrechte pro Agent setzen, bevor produktive Agents starten.
  • API-Keys im Vault ablegen statt in Agent-Instruktionen.
  • Channels für abteilungsübergreifende Kommunikation mit Agents nutzen.
  • Permissions für Everyone schließen, bevor du jemanden einlädst; neue Agents sind sonst für alle Mitglieder verwaltbar (siehe Komplett-Setup).
