GrundlageWas ist OpenBot?

OpenBot ist ein local-first Desktop-Workspace für persistente KI-Mitarbeiter. Er führt unterschiedliche Agent-CLIs und Modell-APIs über ein einheitliches Interface zusammen und stellt jedem Agent einen eigenen Workspace, einen Nachrichtenspeicher und einen eingebetteten Browser bereit.

Unterstützte Provider

GruppeProvider und CLIs
Coding-CLIsCodex, Claude Code (Antigravity CLI), Grok CLI, OpenCode, Gemini
IDE-AgentsCursor, Cline, GitHub Copilot
WeitereKimi, Devin, Mistral Vibe, Hermes Agent
CustomOpenAI-kompatible Endpunkte und eigene ACP-Agents

Jeder Provider nutzt seine eigene lokale CLI-Installation. OpenBot kopiert keine Credentials; jeder Provider verwaltet seinen eigenen Login-State.

Wichtig: Agents laufen mit danger-full-access und approvalPolicy: never. Sie können Dateien ändern, Befehle ausführen, das Netzwerk nutzen und den Browser steuern, ohne Bestätigung pro Aktion. Das ist eine bewusste Produktentscheidung, keine Sicherheitslücke. Wie du das mit Zugriffsstufen eingrenzt, zeigt der Komplett-Setup-Guide.

Lizenz

OpenBot steht unter der PolyForm Noncommercial 1.0.0-Lizenz. Für kommerzielle Nutzung ist eine separate Lizenz nötig (openbot.run/pricing). Bis 1. Dezember 2026 ist die kommerzielle Nutzung kostenlos.

Teil 1 · Installation

Teil 1Installation

macOS

Anforderungen: macOS 13+ (Apple Silicon oder Intel).

1

Herunterladen

DMG-Datei von openbot.run laden.

2

Installieren

App in den Ordner Applications ziehen.

3

Provider einrichten

Beim ersten Start Provider-CLIs über Settings → Providers einrichten.

Builds sind signiert und notarisiert. Provider-CLIs lädt OpenBot auf Wunsch selbst herunter und pinnt die Version.

Windows

Anforderungen: Windows 10+ (x64). x64-Installer herunterladen und ausführen; neuere Releases sind signiert, ältere nicht. Provider über Settings → Providers einrichten.

Dynamic Island und Agent-Dock sind ab 0.67.0 auf Windows verfügbar.

Linux

Anforderungen: Linux x64 oder arm64.

chmod +x openbot-*.AppImage ./openbot-*.AppImage

Ubuntu 23.10+ und Debian 13 brauchen ein AppArmor-Profil:

# AppArmor-Profil installieren sudo cp build/linux/openbot.apparmor /etc/apparmor.d/openbot sudo apparmor_parser -r /etc/apparmor.d/openbot
Niemals --no-sandbox verwenden.

Für einen dauerhaften Linux-Server richtet ein Installationsskript einen systemd-Service auf Ubuntu 24.04 oder 26.04 ein:

curl -fsSL https://openbot.run/install.sh | bash openbot login

Docker

Das Docker-Image läuft headless auf linux/amd64 und linux/arm64.

# Mit seccomp-Profil starten docker run --security-opt seccomp=openbot.json \ ghcr.io/nightly-labs/openbot:latest # Dann einloggen openbot login
Remote Desktop auf Docker-Servern zeigt ab 0.72.0 einen Desktop mit dem OpenBot-Logo.

Nix

OpenBot ist als Nix-Flake verfügbar:

nix run github:nightly-labs/openbot

Provider-CLIs einrichten

OpenBot lädt die meisten Provider-CLIs selbst herunter und pinnt sie. Alternativ gibst du bereits installierte CLIs über Umgebungsvariablen an (siehe Konfiguration). Jeder Provider braucht einen eigenen Sign-in; OpenBot überträgt keine Credentials zwischen Providern.

Eine Schritt-für-Schritt-Anleitung für Ubuntu und Docker auf einem VPS steht in Guide 04 der offiziellen Guides.

Teil 3 · Architektur

Teil 3Architektur

Electron Main

Hauptprozess

Lokaler Codex App Server über stdio, Claude Agent SDK über Stream-JSON, SQLite-Event-Log, typisiertes IPC, sandboxed Browser-View.

Renderer

UI-Schicht

SolidJS. Preload exponiert nur eine typisierte window.openbot-API, kein direkter Node-Zugriff aus dem Renderer.

Account API

Cloud-Backend

TanStack Start auf Cloudflare Workers mit D1 (SQLite) und R2 (Objekte). Verwaltet Konten, Einladungen, Mitgliedschaften, nicht Chats oder Befehle.

Remote Access

WebRTC-Verbindung

Team-API auf Loopback; Clients verbinden sich per WebRTC. Signal überträgt nur Setup-Nachrichten, coturn ist der TURN-Fallback. Chats, Dateien und Remote-Desktop-Media bleiben lokal.

Package-Struktur

src/main/ ← Electron-Hauptprozess src/backend/ ← Backend-Logik src/preload/ ← Preload-Script src/renderer/ ← SolidJS-UI apps/auth-api/ ← Cloudflare-Workers-API apps/status/ ← Statusseite packages/contracts/ ← Shared Types packages/i18n/ ← 15 Sprachen inkl. RTL (Arabisch, Hebräisch)

Dateianhänge

  • Bis zu 100 MB pro Datei
  • Bis zu 250 MB pro Nachricht
  • Bis zu 10 Dateien pro Nachricht
  • Unterstützte Typen: MP3, MOV, MP4, ZIP, SVG und alle weiteren Dateitypen
Teil 4 · Daten & Sicherheit

Teil 4Daten und Sicherheit

Verzeichnisstruktur

~/OpenBot/Agents/<id>/ ← Workspace jedes Agents ~/OpenBot/Shared/ ← gemeinsame Dateien ~/OpenBot/Shared/Transfers/ ← übertragene Dateien userData/openbot.db ← SQLite-Datenbank ~/.codex, ~/.claude, ~/.grok … ← Provider-State, jeweils eigenes Home ~/Library/Application Support/OpenBot/provider-runtimes/ ← Provider-CLIs (macOS)

Provider-State

Jede Provider-CLI verwaltet ihren State in einem eigenen Home-Verzeichnis: ~/.codex, ~/.claude, ~/.grok, ~/.gemini, ~/.cursor, ~/.cline, ~/.kimi, ~/.copilot, ~/.vibe, ~/.hermes. OpenBot kopiert keine Credentials zwischen Providern.

Sicherheitshinweis: Lokaler Vollzugriff ist eine Produktentscheidung, kein Sicherheitsmodell. Agents können auf Host-Pfade außerhalb ihrer Workspaces zugreifen. Sicherheitslücken über SECURITY.md melden, nicht in öffentlichen Issues.

Datenschutz

OpenBot exportiert anonymisierte Diagnosedaten nur mit ausdrücklicher Zustimmung. Chats, Dateien und Befehle verlassen den lokalen Server nicht über Cloudflare. Die vollständige Datenschutzrichtlinie steht in PRIVACY.md im Repository.

Agent-Import

Agents lassen sich aus einem Grok-Bot-Export (.zip) importieren. Übernommen werden Skills, Routinen, Memories und Workspace-Dateien, aber kein Chat-Verlauf. Schritte in Guide 06 der offiziellen Guides.
